## 2. خط أساس المستودع والبنية

المكدس القائم الذي تمت مراجعته يتضمن Expo / React Native / React مع TypeScript، وSupabase PostgreSQL وEdge Functions.

المكونات الموجودة في المستودع:
- Central AI Router وAgent Orchestrator.
- توجيه نماذج حسب الأدوار: chat وplanner وworker وreviewer وsummarizer.
- Tool Registry يتضمن أدوات connected_app وweb.search، مع اشتراط موافقة لأداة الكتابة.
- Brain Router كطبقة استقبال/مصادقة/استخدام/حفظ نتائج وتفويض التنفيذ إلى AI Router.
- Persistent Task Queue مع claim وlease وheartbeat وretry/backoff وتسوية الحالات والإلغاء للمهام queued.
- Worker وScheduler موجودان، لكن نطاق المعالجة الحالي في الكود الذي تمت مراجعته يقتصر على `brain_task`.
- HIMS ونظام المحادثة والرصيد/الاستهلاك والذاكرة الحالية أنظمة قائمة يجب الحفاظ عليها.

## 4. نتائج مراجعة الأمن

أظهر تقرير Supabase Advisor:
- 12 تحذيرًا من نوع `rls_enabled_no_policy`.
- تحذيرين متعلقين بوجود extensions في schema عامة.
- تحذيرًا واحدًا لوظيفة SECURITY DEFINER متاحة لـ anon.
- 73 تحذيرًا لوظائف SECURITY DEFINER متاحة لـ authenticated.
- Leaked Password Protection غير مفعّل.
- تحذيرات أداء تشمل مفاتيح خارجية غير مفهرسة وفهارس غير مستخدمة وسياسات permissive متداخلة.

### تفسير النتائج والإجراء المطلوب

1. لا يعني غياب Policy على جدول أنه مكشوف تلقائيًا؛ يجب فحص grants وRLS وطريقة وصول الخدمات. بعض الجداول التي تمت مراجعتها داخلية ولا تملك grants مباشرة لـ anon/authenticated.
2. يجب مراجعة كل SECURITY DEFINER على حدة: المالك، وsearch_path، والتحقق من هوية المستدعي، والصلاحيات، وما إذا كان التنفيذ مقصودًا. لا تُجرى عمليات revoke جماعية.
3. تفعيل Leaked Password Protection تغيير أمني مرغوب، لكن يجب أولًا التحقق من إعدادات Auth الحالية وأثره على التسجيل وتغيير كلمات المرور، ثم تفعيله عبر إعدادات المشروع المعتمدة والتحقق منه.
4. تحذيرات الفهارس والأداء لا تُعالج ضمن دفعة أمنية عشوائية؛ تُراجع وفق استعلامات فعلية وخطة قياس.
5. لا توجد في هذه الدفعة تغييرات RLS أو grants أو وظائف SECURITY DEFINER أو إعدادات Auth.

### جداول الوكلاء وسياسات الوصول

تمت مراجعة سياسات وجداول منها:
- `agent_task_jobs` مع سياسة قراءة مرتبطة بـ `user_id = auth.uid()`.
- `agent_workspaces` و`agent_workspace_steps` و`agent_workspace_reviews` و`brain_task_contexts` و`brain_task_steps` و`task_ledger` مع سياسات قراءة مرتبطة بالمالك/المستخدم أو صلاحية الإدارة بحسب الجدول.
- `agent_step_usage` و`agent_tool_execution_checkpoints` لم يظهر لهما Policies أو grants مباشرة لـ anon/authenticated في الفحص المنفذ؛ يلزم توثيق نمط الوصول الخادمي قبل أي تعديل.

## 5. الفجوات المعمارية ذات الأولوية

| المجال | الحالة المرصودة | المطلوب |

| Sandbox | لا يوجد إثبات كافٍ لبيئة تنفيذ كود معزولة مكتملة | بناء/تكامل sandbox قبل تشغيل كود غير موثوق |
| Cloud Browser | لا يوجد إثبات كافٍ لمحرك متصفح سحابي مكتمل | تصميم العزل والحماية من SSRF والموافقات |
| Multi-Agent Runtime | أجزاء من Orchestrator وتوجيه الأدوار موجودة | استكمال التنسيق والتوازي وحدود الموارد |

| Model Catalog | تداخل بين إعدادات/كتالوجات قديمة وتشغيلية | توحيد تدريجي بعد تحليل التبعيات |
