# خطة تطوير واجهة Suly Agent AI — برومبتات مرتبة حسب المجهود

هذا الملف يقسّم طلباتك إلى **6 برومبتات مستقلة**، مرتبة من الأسرع إلى الأكبر، بحيث يمكن تنفيذ كل برومبت منفصلًا دون كسر الباقي.

---

## قواعد مشتركة (تُلصق مع كل برومبت)

```text
المشروع: Suly Agent AI — Expo SDK 58 / React Native 0.88 / TypeScript.
الفرع: release/v1. المسار: /home/ubuntu/repo/apps/mobile

قواعد إلزامية:
1) استخدم متغيرات الثيم الموجودة فقط: src/theme/colors.ts و src/theme/theme.ts.
   لا تضف ألوانًا جديدة خارج الثيم. لو احتجت درجة، أضفها كـ token باسم واضح.
2) التطبيق عربي RTL. كل النصوص الجديدة عربية فصحى مبسطة، وأي رقم/كود LTR.
3) ممنوع استخدام Alert.alert للواجهات الجديدة (يبقى فقط للأخطاء الحرجة).
   استخدم مكوّنات داخل التطبيق: BottomSheet / Toast / Dialog.
4) لا تغيّر منطق الـ backend ولا أسماء الجداول ولا الـ Edge Functions إلا لو مطلوب صراحة.
5) قبل التسليم شغّل: npm run typecheck && npm test -- --runInBand
   وحدّث/أضف اختبارات Jest عند تغيير منطق قابل للاختبار.
6) لا تستخدم مكتبات UI جاهزة ثقيلة. مسموح فقط بمكتبات صغيرة ومحددة يذكرها البرومبت.
7) حافظ على دعم Web (react-native-web) وAndroid؛ أي كود خاص بمنصة يوضع في ملف .web.tsx أو داخل Platform.select.
8) لا تحذف أي وظيفة موجودة (سجل المحادثات، HIMS، الوسائط، الرصيد) أثناء إعادة التصميم.
```

**ترتيب التنفيذ المقترح:** 1 ← 2 ← 3 ← 4 ← 5 ← 6
**الاعتماديات:** البرومبت 4 ينشئ مكوّنات مشتركة (BottomSheet/Toast) يعاد استخدامها في 2 و5. لو أردت تنفيذها بالتوازي، نفّذ 4 أولًا.

## البرومبت 1 — الهوية والأزرار الأساسية (سريع: 30–60 دقيقة)

```text
المهمة: تصحيح الهوية والأزرار الأساسية في تطبيق Suly Agent AI.

الملفات: apps/mobile/app/(protected)/chat.tsx
        apps/mobile/app/(protected)/_layout.tsx
        apps/mobile/src/features/admin/AdminShell.tsx
        apps/mobile/src/features/settings/SettingsScreen.tsx
        apps/mobile/app.config.ts

المطلوب:
1) اسم التطبيق الظاهر على الجهاز: "Suly" فقط (app.config.ts → name).
   لكن داخل المحادثة يظهر العنوان "Suly Agent AI" مع مؤشر أخضر صغير "متصل".
   احذف أي اسم قديم أو نقطة أو شعار نصي مكرر بجانب العنوان.
2) لوحة التحكم للأدمن فقط:
   - زر/أيقونة لوحة التحكم في شات لا يظهر إلا لو الحساب أدمن (suly_is_admin).
   - عنصر لوحة التحكم في الـ Drawer يختفي تمامًا لغير الأدمن.
   - حماية المسار: app/(protected)/admin/_layout.tsx يعمل redirect للشات لو المستخدم ليس أدمن.
   - لا تُظهر أي نص يوحي بوجود لوحة تحكم لغير الأدمن.
3) اسم الحساب: أي مكان يظهر "smsmai" أو "SMSM AI" كاسم مستخدم/عرض يتحول إلى "Suly".
   الاسم يُقرأ من profile.full_name مع fallback "Suly".
4) زر إرسال الرسالة: تصميم احترافي (دائري، لون primary، أيقونة سهم/طائرة، حالة disabled باهتة،
   وحالة sending بمؤشر تحميل صغير). لا نص داخل الزر.
5) زر "+" أعلى الشات: أيقونة مميزة (Plus داخل شكل دائري ناعم) لإنشاء محادثة جديدة والانتقال إليها فورًا.
   بجانبه أيقونة مشاركة المحادثة (التنفيذ التفصيلي للمشاركة في البرومبت 4).

معايير القبول:
- حساب عادي لا يرى أي أثر للوحة التحكم (لا زر، لا عنصر Drawer، ولا وصول بالرابط).
- حساب أدمن يرى الزر ويعمل.
- اسم التطبيق على الجهاز Suly، وداخل الشات Suly Agent AI + نقطة اتصال خضراء.
- typecheck وtests ناجحة.
```

## البرومبت 2 — أزرار الرسائل التفاعلية (سريع/متوسط: 45–90 دقيقة)

```text
المهمة: إعادة تصميم أزرار أسفل الرسائل في MessageBubble بشكل تفاعلي احترافي.

الملف: apps/mobile/src/features/chat/components/MessageBubble.tsx
       (وتعديل بسيط في apps/mobile/app/(protected)/chat.tsx لتمرير onEdit)

المطلوب:
1) رسالة المستخدم: زر واحد فقط "تعديل".
   - عند الضغط: يُعاد نص الرسالة إلى مربع الكتابة (ChatComposer) ويُحدد المؤشر في نهايته.
   - عند الإرسال: تُرسل كطلب جديد (رسالة مستخدم جديدة)، ولا تُعدّل الرسالة القديمة في قاعدة البيانات.
   - لا تعرض "نسخ" أو "مشاركة" لرسائل المستخدم.
2) رسالة النموذج: ثلاثة أزرار فقط: "نسخ" + "إعجاب" + "عدم إعجاب".
   - شكل تفاعلي: أيقونات SVG/رموز نظيفة، خلفية دائرية خفيفة، حالة hover/pressed،
     وحالة محددة (filled) عند الإعجاب أو عدم الإعجاب بلون primary/تحذيري هادئ.
   - animation خفيف عند التفعيل (scale 1 → 1.08 → 1) باستخدام Animated API، بدون مكتبات جديدة.
   - "نسخ" يعرض Toast أنيق "تم النسخ" بدل Alert، ويغيّر الأيقونة إلى ✓ لثانيتين.
   - الإعجاب وعدم الإعجاب متبادلان: تفعيل أحدهما يلغي الآخر، والضغط مرة أخرى يلغي التقييم.
   - احذف "مشاركة" و"إعادة" من صف الأزرار. أعد التوليد يبقى متاحًا بالضغط المطول على الرسالة
     (Long Press → قائمة صغيرة فيها "إعادة التوليد").
3) الأزرار تظهر فقط بعد انتهاء streaming، وتكون خفيفة بصريًا (opacity 0.7) وتزيد عند اللمس.

معايير القبول:
- لا يوجد أي زر زائد عن المطلوب.
- التعديل يرسل طلبًا جديدًا فعليًا (رسالة جديدة في السجل).
- التقييم يُحفظ في قاعدة البيانات كما هو الآن (نفس الدالة الحالية).
- لا Alert.alert في هذه المسارات.
```

## البرومبت 3 — تنسيق الردود بشكل فاخر (متوسط: 2–4 ساعات)

```text
المهمة: جعل ردود النموذج منسقة وجميلة (عناوين، نقاط، أكواد) بدل نص مسطح.

الملفات: supabase/functions/_shared/identity_context.ts   (قواعد التنسيق في الـ system prompt)
        apps/mobile/src/features/chat/components/MessageBubble.tsx  (عرض Markdown)
        apps/mobile/src/features/chat/components/MarkdownView.tsx   (ملف جديد)

المطلوب:
1) Backend (system prompt) — أضف قسم "أسلوب الرد" إلى buildSulyIdentityContext:
   - ابدأ بجملة قصيرة تصل مباشرة للجواب، بدون مقدمات مجاملة طويلة.
   - استخدم عناوين Markdown (## / ###) عند وجود أكثر من فكرة.
   - فقرات قصيرة (2–4 أسطر كحد أقصى)، وقوائم نقطية عند التعداد.
   - **تعريف المصطلحات المهمة** بالخط العريض، والأكواد داخل ``` مع تحديد اللغة.
   - جداول Markdown عند المقارنة بين خيارين أو أكثر.
   - لا تكرر السؤال، ولا تختم بجملة "هل تريد المزيد؟" في كل رد.
   - الحد الأقصى الافتراضي: 250 كلمة إلا لو طلب المستخدم تفصيلًا.
2) Frontend — مكوّن MarkdownView يدعم: عناوين h1..h3 بمقاسات متناسقة، bold/italic،
   قوائم مرقمة ونقطية، اقتباس، جدول بسيط، كود inline، وكتلة كود بخلفية داكنة وزر نسخ.
   استخدم مكتبة خفيفة واحدة فقط: react-native-markdown-display (أو محلل Markdown صغير مكتوب يدويًا
   لو رفضت المكتبة). لا تنسخ مكتبات ضخمة.
3) التنسيق البصري: line-height 1.75 للعربية، حجم 15–16، تباعد 12 بين العناصر،
   عرض أقصى 680px على Web، ومحاذاة RTL مع الحفاظ على LTR للأكواد والأرقام.
4) Streaming: أثناء الكتابة اعرض النص الخام (بدون Markdown) لتفادي القفزات،
   ثم أعد التنسيق عند اكتمال الرسالة.

معايير القبول:
- رد فيه عناوين وقائمة وكود يظهر منسقًا بشكل صحيح على Web وAndroid.
- لا انكسار في RTL، ولا تمرير أفقي غير مطلوب لكتل الكود (استخدم scroll داخلي).
- اختبار Jest لمحلل Markdown لو كُتب يدويًا.
```

## البرومبت 4 — نظام اللوحات والرفع والمشاركة (متوسط/كبير: 4–6 ساعات)

```text
المهمة: استبدال كل اللوحات الرمادية البدائية بنظام Bottom Sheet فاخر موحّد.

ملفات جديدة:
  apps/mobile/src/components/ui/BottomSheet.tsx
  apps/mobile/src/components/ui/Toast.tsx
  apps/mobile/src/components/ui/IconButton.tsx
  apps/mobile/src/features/chat/components/AttachSheet.tsx
  apps/mobile/src/features/chat/components/ShareConversationSheet.tsx

المطلوب:
1) BottomSheet: خلفية معتمة (rgba 0.55) + blur خفيف على Web، لوح بزوايا 24،
   مقبض سحب صغير، ظل ناعم، ارتفاع متحرك (Animated spring)، إغلاق بالسحب للأسفل أو بالضغط خارج اللوح.
2) AttachSheet (زر + داخل مربع الكتابة):
   ثلاث بطاقات أفقية أنيقة: "صورة" / "فيديو" / "ملف" بأيقونات line-style،
   خلفية surface مع حدود divider، توهج خفيف عند الضغط، ووصف سطر واحد تحت كل عنوان.
   لا تستخدم Alert أو ActionSheet الرمادي.
3) ShareConversationSheet (أيقونة المشاركة أعلى الشات):
   - مفتاح "عام / خاص" واضح (Switch مخصص بألوان الثيم).
   - عند "عام": إنشاء/إرجاع رابط مشاركة (RPC أو جدول conversations.share_token موجود أو يُضاف)
     مع زر "نسخ الرابط" وToast تأكيد.
   - عند "خاص": إلغاء الرابط وإظهار نص "المحادثة خاصة بحسابك فقط".
   - لو أردت مشاركة نصية سريعة، أضف زر "مشاركة كنص" يستخدم Share API الأصلي.
4) Toast: بديل أنيق لكل Alert.alert غير الحرجة، يظهر أعلى الشاشة، خلفية سطحية، حدود ناعمة،
   أيقونة حسب النوع (نجاح/خطأ/معلومة)، ويختفي بعد 2.5 ثانية مع fade.
5) الإشعارات/اللوحات القديمة: ابحث عن كل Alert.alert و Modal بسيط في الشات والوسائط والإعدادات
   واستبدلها بالتوست أو BottomSheet حسب الحالة.

معايير القبول:
- لا يوجد أي لوح رمادي أو Alert افتراضي في مسارات الرفع والمشاركة.
- الألوان كلها من الثيم، وتعمل على الوضع الداكن (الافتراضي) والفاتح.
- لا كسر في تدفق الرفع الحالي (Cloudinary + media-service) ولا في الضغط على +.
```

## البرومبت 5 — إصلاحات وظيفية حرجة: المصادقة والرد والصوت (متوسط/كبير: 4–6 ساعات)

```text
المهمة: إصلاح ثلاثة أعطال وظيفية تمنع الاستخدام اليومي.

أ) المصادقة والبريد:
الملفات: apps/mobile/src/features/auth/auth-service.ts، apps/mobile/app/(auth)/login.tsx، app.json/app.config.ts
المشكلة: رابط تأكيد البريد يفتح صفحة خطأ ثم يُطلب من المستخدم إدخال بياناته مرة أخرى.
المطلوب:
1) ضبط redirect: emailRedirectTo = "suly-agent-ai://auth/callback" (scheme موجود في app.config.ts)،
   وإضافة نفس الرابط إلى Supabase → Authentication → URL Configuration → Redirect URLs.
2) في التطبيق: مستمع deep link يقرأ tokens من الرابط ويعمل setSession تلقائيًا،
   ثم يوجّه للشات مباشرة بدون إعادة تسجيل دخول.
3) بديل أسهل وأفضل تجربة: تفعيل 6-digit OTP بدل الرابط
   (signInWithOtp + verifyOtp) في شاشة واحدة: بريد → كود → دخول.
   اعرض الوضعين مع مفتاح تبديل، واجعل OTP هو الافتراضي.
4) الاسم الظاهر بعد الدخول: "Suly" وليس smsmai، ويُقرأ من profile.full_name.
5) رسائل الخطأ عربية واضحة (بريد غير مؤكد، كود خاطئ، محاولات كثيرة).

ب) خطأ "أُوقف الرد. رسالة المستخدم محفوظة ويمكن إعادة المحاولة":
الملفات: apps/mobile/app/(protected)/chat.tsx (سطر ~124)، src/features/chat/chat-service.ts، src/lib/network/sse-transport.ts
المطلوب:
1) تشخيص: سبب الإيقاف الفعلي (استجابة 404/500 من ai-router أو abort من request سابق).
2) لا تعرض شريطًا أحمر عند ضغط بطاقات الاقتراحات أو الإرسال العادي.
3) معالجة إعادة المحاولة: لو فشل الطلب، اعرض زر "إعادة المحاولة" داخل فقاعة الخطأ،
   وأعد استخدام نفس نص المستخدم بدون تكراره في السجل.
4) لو conversationId غير موجود بعد، أنشئ المحادثة أولًا ثم أرسل (منع 404).
5) شريط الخطأ: تصميم هادئ (خلفية تحذيرية شفافة، أيقونة، نص قصير) وليس شريطًا أحمر فاقعًا.
6) بطاقات الاقتراحات الأربع: اجعل محتواها متغيرًا (مجموعات مختلفة حسب وقت اليوم/آخر محادثة)،
   وكل بطاقة ترسل نصها وتُظهر ردًا فعليًا.

ج) تسجيل الصوت:
الملف: apps/mobile/src/features/chat/components/ChatComposer.tsx
المطلوب:
1) التسجيل مستمر حتى يضغط المستخدم "إيقاف/إرسال" (بدون auto-stop).
2) زر ميكروفون احترافي: دائري، تدرج من الثيم، حالة نشطة بنبض خفيف + عدّاد زمني (00:12).
3) أثناء التسجيل: زر إرسال يتحول إلى "إرسال الصوت" وأيقونة إلغاء (X) بجانبه.
4) بعد الإيقاف: النص يظهر داخل مربع الكتابة قابلًا للتعديل قبل الإرسال.
5) معالجة الأذونات برسالة داخلية أنيقة (BottomSheet) لا Alert.
6) fallback على Web: لو التعرف غير مدعوم، اعرض زر تسجيل معطّل مع تلميح.

معايير القبول:
- تسجيل الدخول عبر OTP يعمل من البداية للنهاية على Android.
- لا يظهر شريط الخطأ عند الاستخدام العادي أو ضغط الاقتراحات.
- التسجيل الصوتي يستمر أكثر من 30 ثانية حتى يوقفه المستخدم.
- typecheck وtests ناجحة، وإضافة اختبارات لمنطق retry وOTP parsing.
```

المهمة: تلميع نهائي بعد تنفيذ البرومبتات 1–5.
